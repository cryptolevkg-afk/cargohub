# CargoHub — backend-каркас

Скелет REST API на Node.js/Express + PostgreSQL под техническое задание
«Универсальная платформа карго-доставки и грузоперевозок».

**Проверено вживую**: схема применена к реальному PostgreSQL 16, сервер поднят,
и через него прогнан полный сценарий по HTTP — регистрация клиента/перевозчика/
грузоотправителя/сотрудника склада → добавление посылки → приёмка на складе
(объёмный вес считает сама БД) → консолидация и оплата с кошелька → создание
заявки на бирже → ставка перевозчика → назначение → GPS → рейс по этапам до
"delivered" → админ-дашборд с реальной агрегацией по SQL. Всё отработало без
ручных правок кода.

## Запуск локально (без Docker)

```bash
cp .env.example .env        # заполнить DATABASE_URL и JWT_SECRET
createdb cargohub
npm install
npm run migrate             # применить schema.sql
npm run dev
```

## Запуск через Docker (рекомендуется для деплоя)

```bash
docker compose up --build
```

Поднимет PostgreSQL и API одной командой; схема применяется автоматически при
первом старте контейнера БД. API будет доступен на `http://localhost:4000`.

## Деплой на Render через render.yaml (рекомендуется)

В архиве уже лежит `render.yaml` в корне (рядом с папкой `backend/`) — это
Render Blueprint, который одной кнопкой поднимает и API, и managed
PostgreSQL, без ручных настроек. Схема БД применяется автоматически при
каждом старте сервиса (идемпотентно — `scripts/migrate.js` проверяет,
есть ли уже таблицы, и пропускает миграцию при повторных деплоях).

1. Создайте новый репозиторий на GitHub и запушьте в него **содержимое
   этого архива целиком** — так, чтобы `render.yaml` лежал в корне
   репозитория, а рядом была папка `backend/`:
   ```bash
   git init
   git add .
   git commit -m "CargoHub backend"
   git branch -M main
   git remote add origin https://github.com/<ваш-аккаунт>/cargohub-backend.git
   git push -u origin main
   ```
2. Зайдите на [render.com](https://render.com), зарегистрируйтесь (можно
   через GitHub) и нажмите **New → Blueprint**.
3. Выберите только что созданный репозиторий. Render сам найдёт
   `render.yaml`, покажет план (1 web service + 1 PostgreSQL) — нажмите
   **Apply**.
4. Дождитесь окончания билда (несколько минут). `JWT_SECRET` Render
   сгенерирует сам (`generateValue: true`), `DATABASE_URL` подставит
   автоматически из связанной базы (`fromDatabase`).
5. Откройте `https://<имя-сервиса>.onrender.com/health` — должно
   вернуться `{"ok":true}`.
6. Вставьте этот URL в настройки мобильного прототипа (шестерёнка рядом
   с переключателем ролей) и нажмите «Подключить».

Обратите внимание: на бесплатном плане Render Web Service «засыпает»
после ~15 минут без запросов и просыпается около 30–50 секунд на первый
запрос — это нормально для бесплатного тарифа, не баг.

### Деплой на Railway (альтернатива, без render.yaml)

1. Создать аккаунт на railway.app, подключить репозиторий или загрузить
   папку `backend/` как отдельный сервис
2. Добавить плагин PostgreSQL — Railway сам выдаст `DATABASE_URL`
3. Прописать `DATABASE_URL` и свой `JWT_SECRET` в переменных окружения
4. В качестве Start Command указать `node scripts/migrate.js && node src/server.js`
   (тот же идемпотентный migrate.js, что используется в render.yaml)
5. Включить Generate Domain — получите публичный URL

Для прод-нагрузки в дальнейшем — вынести БД на управляемый Postgres
(например Amazon RDS, Yandex Managed PostgreSQL) и запускать API в нескольких
инстансах за балансировщиком.

## Структура

```
render.yaml              — Render Blueprint: web service + managed PostgreSQL
schema.sql               — полная DDL-схема (пользователи, роли, склады, посылки,
                           отправки, тарифы, таможня, страхование, биржа перевозок,
                           рейсы, кошелёк, документы, чат, отзывы, поддержка, аудит)
scripts/
  migrate.js             — идемпотентный runner schema.sql (проверяет наличие
                           таблиц перед применением — безопасно при каждом деплое)
src/
  server.js             — точка входа, монтирование роутов
  db.js                 — пул подключений к PostgreSQL
  middleware/auth.js    — JWT-аутентификация и проверка ролей
  routes/
    auth.routes.js       — регистрация, вход
    packages.routes.js   — посылки клиента, приёмка на складе, консолидация
    freight.routes.js    — заявки биржи, ставки, назначение перевозчика, рейсы
    wallet.routes.js      — баланс, пополнение, история операций
    warehouses.routes.js — справочник складов, персональные адреса-ячейки
    admin.routes.js      — дашборд, управление пользователями, KYC, поддержка
```

## Роли и доступ

Роли пользователя (`user_roles`) кладутся в JWT при логине и проверяются
через `requireRole(...)` в мидлваре. Один пользователь может иметь
несколько ролей одновременно (например `client` + `shipper`).

- Вебхуки/очереди для push- и SMS-уведомлений на каждый статус-переход

  статусов посылок до прибытия на склад
- Rate limiting, валидация входных данных через zod на каждом роуте,
  логирование запросов, миграции через отдельный инструмент (например knex/prisma)
  вместо прямого `schema.sql` в проде
